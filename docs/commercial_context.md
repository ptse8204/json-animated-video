# Commercial Context

## Existing adjacent products

The market already has:

- AI video cutouts
- background removal
- video-to-Lottie converters
- programmatic video generation
- website animation formats
- browser animation runtimes

Therefore MotionJSON should not compete as a generic cutout or video-to-Lottie tool.

## Differentiation

MotionJSON should focus on:

```text
AI extraction
+ reusable object asset package
+ JSON edit graph
+ website embed/runtime
+ resource-aware rendering
+ rights metadata
```

## Why website graphics are a strong wedge

Website teams already understand reusable assets, embeds, animation states, and performance budgets.

Use cases:

```text
ecommerce hero graphics
interactive product demos
education explainers
creator motion stickers
landing-page visual effects
brand asset libraries
```

## Commercial safety

Avoid unrestricted “grab anything from any online video.”

Early commercial scope should be:

```text
creator-owned uploads
licensed stock footage
brand-owned media
public domain / Creative Commons
opt-in creator asset libraries
```

Every extracted asset should carry:

```text
source
license
attribution flag
creator approval flag
commercial-use flag
asset lineage
```

## Moat

Do not rely on “we use SAM2” as a moat.

Build moat through:

```text
quality scoring
mask correction UX
fast runtime
resource profiling
export compatibility
asset library
rights metadata
template workflows
developer API
```
